# TDD Rationalizations

| Excuse | Reality |
| --- | --- |
| “It is only one line.” | One line can change every request. Test observable behavior. |
| “I will add tests after it works.” | A test written after implementation may only confirm the implementation. |
| “The existing suite covers it.” | Name and run the exact covering test, or add one. |
| “The test is flaky.” | Investigate the source; retries do not create confidence. |
| “The deadline is more important.” | Deadline pressure increases the need for fast deterministic feedback. |
